## 1. 开发原则

### 1.1 小步迭代
- **每次只做一个功能**，做完验证通过再进入下一步
- 每个步骤完成后，软件**可以正常运行**（哪怕功能不全）
- 不出现"代码写到一半不能运行"的状态

### 1.2 先稳后快
- 先搭骨架（项目结构、DI、日志），再填业务
- 先做核心流程（监控→存储→显示→粘贴），再做增强功能
- 边界情况和异常处理与功能同步完成，不后补

### 1.3 可验证
- 每一步完成后都有明确的验证方法
- 所有验证方法通过后才能标记完成

## 3. 每日工作流

```
1. 查看 devlog/ 中上一日的日志，了解进展
2. 查看 docs/development-plan.md 确认当前步骤
3. 按计划执行当前步骤的开发
4. 完成步骤后更新 devlog/ 当日日志
5. 如遇阻碍，在日志中记录并调整计划
```
